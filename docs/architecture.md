# 架构与维护边界

项目使用父 Agent 动态委派专业 Agent 的单一主图。HTTP 与 CLI 进入同一个任务服务，模型对话、业务状态、后台作业分别管理。

```text
CLI / Web API → TaskService → graph.py
                   │            ├─ supervisor → delegate → 专业 Agent → supervisor
                   │            ├─ human.py：选题、问答、修改、批准、取消
                   │            └─ 人工确认后发布
                   └─ agents/factory.py → 角色实例 → registry.py 权限与协议检查

专业模型 → StructuredModelAgent → ModelToolRuntime → 已授权工具
父模型   → ModelToolRuntime → 结构化决策
                   └─ ModelAgent：延迟创建 Provider、隔离凭据、关闭自有连接
```

## 主要模块

| 模块 | 负责 | 维护边界 |
| --- | --- | --- |
| `service.py` | 创建任务、人工操作、恢复图、导出与平台服务入口 | 不拼提示词，不直接执行工具 |
| `graph.py` | 主 Agent 上下文、决策校验、执行委派、图连接与发布节点 | 节点名与状态字段属于检查点契约 |
| `human.py` | 人工选题、问答、改稿、批准、取消及对话记录更新 | 不让模型替用户确认或批准 |
| `workflow.py` | 将实际检查点投影为可操作状态与允许的操作 | 这是当前主图的门禁规则，不是旧固定流程 |
| `agents/factory.py` | 配置或注入各角色实现及外部工具 Provider | 实例创建时不发模型请求 |
| `agents/model.py` | 所有真实模型 Agent 共用的 Provider 生命周期 | 非选题角色必须使用自己的配置或环境变量 |
| `agents/structured.py` | 专业模型共享的结构化输出、提示词约束与业务校验 | 选题、调研、创作和审核复用同一执行入口 |
| `agents/runtime.py` | 单次模型与工具循环、调用预算、输出修正 | 不继承父图检查点，不批准或发布 |
| `agents/delegation.py` | 将统一委派转为专业业务输入，落库产物并返回摘要 | 重放同一委派复用已完成结果 |
| `agents/registry.py`、`decisions.py` | 角色白名单、工具/技能授权、决策和产物引用解析 | 以真实结构化上下文校验模型决策 |
| `memory.py` | 模型工作窗口、正文摘录与完整执行存档 | 不用摘要替代版本、人工选题或批准记录 |
| `storage.py`、`team_store.py` | 业务数据、不可变产物、委派账本、长期偏好 | 业务事务与 LangGraph 检查点分别保存 |
| `web/app.py` | HTTP 任务、画像、媒体、作业事件入口 | 复用 TaskService，不实现第二套编排 |
| `web/settings.py` | 模型设置路由、启动配置与 Web 覆盖、角色凭据复制 | 模型配置来源的规则只在这里实现 |
| `web/jobs.py`、`repository.py` | 后台执行、持久化作业、幂等请求、事件 | 同一任务同时只允许一个写作业 |
| `llm/`、`platforms/`、`skills/` | 厂商协议、平台连接、技能权限 | 与内容业务模型分开维护 |

## 本次整理

- 合并选题、父 Agent、专业模型中重复的 Provider 初始化和关闭逻辑；选题复用专业模型的结构化输出入口。
- 将角色组装移入工厂，TaskService 只保留任务服务职责；使用统一 ModelAgent 生命周期关闭自有连接。
- 将人工交互移出主图，统一追加用户消息与恢复主 Agent 的状态更新。
- 将模型设置移出 Web 主入口，配置校验和运行时配置转换使用同一方法。
- 移除选题专属 `AgentConfig.ideation_max_*` 字段，预算统一由 `execution.roles.ideation` 管理；模型、工具、输出修正和父 Agent 协作轮次均默认不限次数，JSON 使用 `null`。
- 移除重复技能工具常量别名、跨模块的间接导出和未使用局部变量；选题入队不再重复校验同一个人工暂停点。
- Runtime 使用普通循环，避免内部图的递归步数限制及重复检查点。父图继续保存业务进展和人工中断；旧检查点类型白名单保留以读取历史数据。
- 修正 README 中“实际图片生成尚未接入”等与当前代码不符的说明。

## 保留的边界与已知限制

`Mock`、规则审核、平台发布服务以及旧编码读取仍有实际入口和测试覆盖，不属于废弃代码。发布前后校验分别保护人工批准、平台幂等和不明回执，不应为了减少行数合并或跳过。

当前没有从任意工具中间步骤恢复专业模型的公开入口；失败会从父图未完成节点重新执行，产物、委派和图片缓存控制重复副作用。历史数据库与存档不在本次清理范围内。

前端的对话、草稿编辑和模型配置组件仍可继续按业务拆分；本次不调整页面布局。接口错误仍使用脱敏的通用提示，缺少可安全展示的服务商错误分类；单独的 supervisor 执行预算也尚未纳入 `execution.roles`。
