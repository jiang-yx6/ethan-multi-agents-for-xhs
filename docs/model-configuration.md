# 模型配置：启动文件与网页设置

每个 Agent 独立选择配置来源。父 Agent 不会隐式复用选题配置；一键应用会为目标 Agent 创建明确的网页配置副本。

专业 Agent 的提示词、执行预算、技能/工具范围以及检索/图片接口属于独立的 `execution` 配置，通过 `--execution-config` 或启动模型文件同级 `execution` 对象提供。网页模型设置只管理文本模型，不覆盖这些执行能力。图片生成接口与文本视觉输入分别配置，详见 [专业 Agent 执行能力](specialist-execution.md)。

| 方式 | 保存位置 | 加载时机 | 生效范围 |
| --- | --- | --- | --- |
| 启动文件 `llm-config.json` | 通过启动参数指定的 JSON 文件 | 服务启动时读取；修改后重启 | CLI，以及选择“跟随启动配置”的 Web Agent |
| 网页独立配置 | 当前 `--data-dir` 下的 `web.db`；密钥单独加密 | 保存后用于下一次执行或重试 | 当前 Web 工作区的对应 Agent |
| 环境变量 | 启动服务的进程环境 | 没有该角色的显式启动模型配置时，由运行时读取 | 跟随启动配置的对应角色 |

网页独立配置完整覆盖该角色的启动模型配置，不与 JSON 按字段混合，不写回文件。其他角色仍保持各自来源。启动文件中的 `extra_body`、`extra_headers`、`token_parameter` 等高级参数，应选择“跟随启动配置”使用。

网页选择“跟随启动配置”并保存，会撤销当前角色的网页覆盖。启动时指定了该角色的模型配置就使用它；否则按角色环境变量和启动默认运行方式处理。保留的网页密钥不会在此模式下被隐式使用。

设置页显示当前生效来源，以及启动基线的文件路径、模型、输出预算和超时。来源下拉框是待保存的选择；“当前生效”标记显示上一次成功保存后的状态。

## 通过文件配置

打开文件本身不会让项目自动读取它。需要在项目根目录启动：

```powershell
uv run --extra web --extra browser xhs --llm-config examples/llm-config.json web
```

也可先设置 `$env:XHS_LLM_CONFIG = "examples/llm-config.json"`，再运行 `xhs web`。启动文件的路径会显示在设置页。CLI 普通任务命令读取启动参数或环境变量，不读取 Web 工作区的模型设置。

例如，在真实的 `review` 角色配置中调整：

```json
{
  "review": {
    "provider": "deepseek",
    "model": "填写实际模型 ID",
    "api_key_env": "XHS_REVIEW_API_KEY",
    "max_tokens": 8192,
    "timeout": 180
  }
}
```

这是角色片段；启动 Web 所需的其他角色配置仍需保留。文件方式修改后重启服务，并在审核 Agent 页面选择“跟随启动配置”后保存。网页上的接口与密钥输入框在跟随模式下只读；切换为“网页独立配置”后才能修改。

## 通过网页配置

1. 打开“技能与模型”，选择对应 Agent，例如审核 Agent。
2. 将配置来源选为“网页独立配置”。
3. 填写模型接口和凭据，设置“最大输出 Token”与“请求超时（秒）”。
4. 点击“保存 Agent 配置”，确认“当前生效”显示网页独立配置，再到失败任务重试。

网页保存不需要重启服务；已经执行中的调用仍使用启动本次作业时取得的配置。切换来源也不会自动重跑任务。一键应用复制页面支持的接口、输出预算、超时和凭据，之后各 Agent 单独保存，互不联动。

## `length` 错误

`length` 表示模型在输出长度上限处停止。默认 `max_tokens` 为 4096，单位是 Token，不是中文字数。Agent 需要完整的结构化结果，截断时会停止执行并明确指出出错角色及本次配置上限。

可以先把该角色的输出预算从 4096 调整到 8192；具体数值需在服务商支持范围内，较长输出可能还需要提高超时。调整的是当前生效来源：网页覆盖存在时，只修改 JSON 不会改变该 Agent 的 Web 调用。

旧网页配置缺少这两个字段时，沿用 `max_tokens=4096`、`timeout=120`；保存新值后用于后续调用。

子 Agent 遇到长度、结构校验或接口执行错误，会把 `failed` 结果交回父 Agent；如果父 Agent 暂停提问，调整该角色生效配置后直接在对话中回复即可重新委派。父 Agent 自身模型错误、配置错误和存储异常仍会使图节点失败，修复后点击重试。已返回的失败委派不会覆盖为成功，新执行使用新 ID，避免丢失失败记录。

结构或来源校验失败的最终错误会注明 Agent 及最后校验问题；执行事件中还会记录每次 `output_validation` 及是否继续修正。先根据具体字段或规则调整要求，不必将所有校验失败都归因于 Token 上限。
